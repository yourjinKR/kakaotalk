# 카톡: 설치된 KakaoTalk PC의 친구·채팅 분석

조사일: 2026-10-22 (Asia/Seoul). 이 문서는 다음 요청에서도 같은 설치본을 다시 조사하지 않고 개발을 이어갈 수 있도록 남긴 정적 분석 기록이다.

## 결론과 범위

설치된 PC 카카오톡의 실행 파일 식별과 PE 리소스 분석을 REA로 수행했다. 설치 패키지의 구조화된 한국어/영어 UI 문자열, 색상, 이미지 상태 선언도 XML 파서로 읽었다. 이 근거로 친구 추가·즐겨찾기·숨김·차단·삭제, 채팅 검색·정렬·상단 고정·읽음·알림, 메시지 전송 상태·답장·삭제를 우선 재현할 수 있다.

**네이티브 코드를 디컴파일하거나 실행 동작을 관찰한 결과는 아니다.** UI 문구는 패키지에 실재하지만, 그 기능의 실행 가능 여부, 서버 처리, 현재 활성화 조건까지 증명하지 않는다. 앱 원본 코드, 이미지, 캐릭터, 폰트를 복사해서 구현하지 않는다. 재현 앱의 데이터 모델과 서버는 독립 설계다.

조사 대상은 설치 프로그램 디렉터리뿐이다. 개인 친구/대화 데이터베이스, 계정 정보, 토큰, 메시지 내용은 읽지 않았고 카카오톡을 통해 메시지를 보내지 않았다.

## 화면 구성에 사용할 수 있는 근거

`color.xml`에서 노랑 `Y100=FEE500`, hover `Y100H=FADA0A`, 눌림 `Y100D=F2D00F`, 대화 배경 후보 `CHATBG01=BACEE0`, 진한 글자 `B85=191919`, 보조 글자 `B40=949494`, 구분선 후보 `B10=E6E6E6`를 관찰했다. 색상 이름과 값은 관찰되었지만 모든 화면에서의 실제 적용 위치가 확인된 것은 아니다.

`Resource.xml`은 즐겨찾기·고정·알림 각각의 on/off 리소스와 normal/hover/disable 상태를 구조화해 선언한다. 패키지 이미지는 구현에 복사하지 않고 CSS와 새로 작성한 아이콘으로 상태를 표현한다.

`font_ko.xml`에는 `Head01 → Font15`, `Head02 → Font13`, `Body01 → Font11`, `Body02 → Font10` 등의 별칭이 있다. 같은 파일의 폰트 선언에는 맑은 고딕이 사용된다. 이 값은 네이티브 폰트 단위로, 브라우저 CSS px와 같다고 단정하지 않는다.

레이아웃 파일 8개는 `.xml` 확장자지만 XML 파싱에 실패하는 불투명 바이트였다. 7개 샘플의 첫 16 bytes는 `39537D0F5AA72E9249DD50DF1180838A`, `FriendListView.xml`은 다른 값이었다. 암호화/압축/직렬화 중 어떤 방식인지 확인하지 않았다. 따라서 그 파일 이름에서 좌우 배치·정확한 픽셀 치수·이벤트 처리를 복구했다고 주장하지 않는다.

## 조사 환경 한계

REA 연결과 `open_binary`는 성공했다. 그러나 `binary_session`의 실제 provider 진단은 다음과 같았다.

- Ghidra: `GHIDRA_INSTALL_DIR` 미설정, Ghidra 12.1.x 설치 경로와 대응 네이티브 디컴파일러를 찾지 못함.
- IDA: `REA_IDA_MCP_CONFIG` 미설정.
- Hopper: Windows 호스트 미지원.

이것은 MCP 등록 오류가 아니다. 설정 변경이나 무관한 도구 설치를 반복하지 않았다. 사용 가능한 portable `inspect_pe_resources`와 로컬 XML 파싱으로 유용한 분석을 완료했다. 선택한 네이티브 세션은 Evidence를 내보낸 뒤 `close_binary`로 닫았다.

개발은 위 명세의 최소 범위를 먼저 완성한다. 이후 실제 화면 관찰이 필요해지면 친구/대화가 노출되지 않는 테스트 계정이나 사용자가 지정한 흐름에서만 검증하고, 실행 중 실제 연락처에 메시지를 보내는 동작은 별도 명시된 요청이 있어야 수행한다. 네이티브 코드 분석이 꼭 필요할 때 이미 설치된 Ghidra/IDA 경로를 확인하여 그 구체적인 공급자 문제만 해결한다.

이어 작업할 때 이 문서와 Evidence JSON을 먼저 읽고, 동일 해시인 설치본에 대해 같은 PE 분석을 반복하지 않는다. 앱 구현 상태는 루트 README와 개발 진행 기록에서 확인한다.
