# 진행 기록 · 친구 관리와 채팅

최종 기록일: 2026-10-24 (Asia/Seoul)

사용자의 목표는 PC에 설치된 카카오톡을 조사해 친구 관리와 채팅에 집중한 개인 메신저를 만드는 것이다. 토큰 사용량에 따라 다음 대화에서 이어 개발할 수 있도록 실제 조사 근거, 구현 범위, 검증 결과와 남은 일을 기록한다.

## 현재 결과

현재 앱 이름은 **나의 톡**이며 React/Vite, Express/Socket.IO, SQLite, Electron으로 구성된다. 같은 로컬 서버에 로그인한 서로 다른 계정이 실제 메시지를 주고받는 독립 앱이다. 카카오톡 계정 로그인, 기존 친구·대화 가져오기, 카카오 서버 연결 또는 카카오톡 통신 프로토콜은 구현하지 않았다.

원본의 정적 리소스에서 확인한 기능 구조와 색상·글꼴을 참고했다. 원본의 모든 화면 동작을 복구한 상태는 아니며, 현재 화면 치수와 일부 흐름은 재현 앱의 구현 판단이다. 설치 앱의 이미지·로고·이모티콘 자산이나 개인 계정 데이터베이스는 복사하지 않았다.

## 구현한 기능

| 영역 | 현재 구현 |
| --- | --- |
| 계정 | 가입, 로그인, 로그아웃, 본인 이름·상태 메시지·아바타 색상 변경, 로컬 데모 계정 |
| 친구 | 같은 서버의 사용자 검색과 ID로 추가, 목록 검색, 프로필, 개인별 표시 이름, 즐겨찾기, 숨김·복귀, 차단·해제, 숨김/차단 관리 창 |
| 채팅방 | 1:1·그룹·나와의 채팅 생성, 기존 1:1/자기 방 재사용, 목록·최근 메시지, 방 검색, 고정·해제, 알림 켜기/끄기, 그룹 이름 변경, 방 나가기 |
| 메시지 | 실제 텍스트 전송, Socket.IO 실시간 갱신, 날짜 구분, 시간, 안 읽은 수와 읽음 위치, 입력 중 표시, 이모지 선택, 대화 검색, 이전 기록 페이지 조회 |
| 권한·상태 | 서버 측 인증·참여자 권한 검사, 1:1 양방향 차단 검사, 로그아웃 세션/소켓 폐기, 전송 재시도의 중복 방지 |
| 저장 | 계정·친구 설정·방·메시지·읽음 위치를 SQLite에 저장, 재시작 후 데이터 유지 |
| 데스크톱 | Electron 창과 로컬 백엔드 실행·종료 코드, 창에서 빌드한 프런트엔드 로드 |

차단은 현재 앱의 정책에 따라 해당 상대와 **1:1 메시지·입력 중 표시를 양방향으로 막으며 그룹에는 적용하지 않는다.** 원본의 차단 해제/재추가 동작에는 서로 다른 정적 안내가 함께 있어 완전한 동일 동작은 확인하지 못했다.

친구 삭제 API는 백엔드에 있으나 화면에서 삭제하는 흐름은 아직 없다. 채팅 목록은 현재 고정 우선·최근 메시지 순으로 표시하며, 원본 리소스에 있는 안 읽은 순/즐겨찾기 순 선택 메뉴는 아직 구현하지 않았다.

## 실행과 저장 위치

Node.js `22.13.0` 이상이 필요하다. 프로젝트 루트 `C:\dev\workspace\vibe-coding\kakaotalk\v3`에서 실행한다.

```powershell
npm install
npm run dev
```

개발 웹 화면은 기본 `http://127.0.0.1:5173`, 백엔드는 `127.0.0.1:4100`이다. Vite가 다른 포트를 사용하면 터미널에 출력된 주소를 따른다. 별도 터미널에서 다음 명령을 실행할 수 있다.

```powershell
npm run desktop
npm test
npm run build
```

- `npm run desktop`: 프런트엔드 빌드 후 Electron 실행. Electron이 가용 로컬 포트에 자체 백엔드를 띄운다.
- `npm test`: 임시 데이터베이스와 실제 HTTP/WebSocket 연결을 사용하는 백엔드 테스트.
- `npm run build`: 배포용 프런트엔드 생성.
- 비어 있는 기본 DB에는 `young`, `seoyeon`, `minjun` 계정이 생성된다. 공통 비밀번호는 `12345678`이다.
- 개발 서버의 기본 DB: `data/talk.sqlite`.
- Electron의 DB: Electron `app.getPath('userData')` 아래 `kakaotalk.sqlite`. 개발 서버 DB와 별도이다.
- 로그인 토큰은 **탭별 `sessionStorage`**에 저장한다. 서로 다른 탭에서 다른 계정으로 로그인할 수 있다. 같은 탭을 새로 고치면 로그인은 유지되지만, 앱/탭을 닫고 다시 시작하면 다시 로그인해야 한다. 친구·대화는 SQLite에 남는다.
- 작성 중 메시지는 현재 메모리 상태에 보관한다. 앱 종료 후 초안 복원은 구현하지 않았다.

서버는 현재 loopback 주소에만 바인딩한다. 다른 PC·모바일의 접속이나 인터넷 배포는 아직 지원 범위에 들어가지 않았다. 백엔드 API·이벤트·제약은 [server/README.md](../server/README.md)에 정리되어 있다.

- SHA-256: `23d0025988d3dd413801823657c5ac00e69945221d973aef7314f220142ab6a5`.
- 실제 REA `inspect-pe-resources` Evidence: `ev_9a4edcd6f1cc4950ab7e6b369c46b5d0280e35ec3939e46c09c573a3b8a9bb49`.
- REA CLI `6.7.0`로 PE32/x86 리소스 트리 25개 entry와 10개 payload를 확인하고 완전한 Evidence JSON을 저장했다. 이 결과는 함수·네트워크·채팅 프로토콜 분석이 아니다.

- 앱 실행, 계정 DB 읽기, 기존 대화 확인 또는 실제 카카오톡 발송은 수행하지 않았다.

## 다음 작업 우선순위

1. **현재 버전 검증 마무리:** Electron 창 내부 로그인·메시지 조작, 종료·재시작, 저장 위치를 확인하고 위 검증 표를 갱신한다. 실제 창 생성과 SQLite 런타임 지원은 확인했다. 개발 서버와 Electron의 기본 서버/DB가 별도라는 점을 고려해 같은 서버에 접속한 두 클라이언트로 검증한다.
2. **친구 관리 마무리:** 삭제 UI, 개인 메모, 숨김/차단/삭제 전환 조합, 추가 검색의 정확한 일치/검색 공개 여부와 연락처 추가 범위를 결정한다. 현재 전화번호로 친구를 찾는 기능은 없다.
3. **채팅 강화:** 답장·첨부파일/이미지, 전송 실패 재시도 UI, 메시지 삭제, 안 읽은 순/즐겨찾기 순 정렬, 모두 읽음, 앱 종료 후 초안 복원 등의 우선순위를 정해 구현한다. 현재는 텍스트 중심이다.
4. **원본 조사 심화:** 개인 정보를 드러내지 않는 범위의 실행 관찰이나 native 엔진을 통한 레이아웃 판독이 필요한지 결정한다. opaque 레이아웃, 실제 여백·크기, 차단 해제 진입 경로, 입력/키보드 규칙은 아직 미확인이다. native 엔진 설치·설정 변경은 구체적인 계획을 만든 뒤 해당 범위의 승인을 받아 진행한다.
5. **실사용 준비:** DB 스키마 버전별 마이그레이션·백업/복원, 세션 보관 방식, 공유 서버/HTTPS·CORS·호스트 설정, 외부 배포와 Windows 설치 패키지를 설계한다. 현재 `CREATE TABLE IF NOT EXISTS`와 초기 schema version 1만 있으며 업그레이드용 마이그레이션 체계는 없다.

카카오의 비공개 프로토콜 연결은 현재 구현 목표에 포함시키지 않았으며, 추가 조사로 필요성이 확인되더라도 독립 앱의 완료 기능과 구분한다.
