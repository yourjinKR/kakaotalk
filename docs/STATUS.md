- 일반/숨긴 친구 삭제: 대상 확인·취소/Escape, 내 방향 관계만 제거, 대화·메시지 수신 유지, ID 재추가와 기존 1:1 방 재사용.
- 삭제 재시도·저장 실패 롤백, 같은 사용자의 다른 창 목록/프로필/새 채팅 선택 갱신. 연결 실패 시 확인창과 재시도 초점 유지.
- 프로필→1:1, 채팅방 목록/검색, 1:1 재사용, 새 그룹 생성/참여자 보기.

- 방 안 읽음 수와 메시지별 미확인 참여자 수, 단조증가 읽음 커서.
- 저장 실패 시 메모리 롤백/임시파일 정리, Windows 일시 파일 잠금의 제한된 재시도, 손상 파일 덮어쓰기 방지.
- 원본 자산을 사용하지 않은 화면, 합성 이름/상태, 반응형 목록/대화 전환.

## 현재 단계와 검증

친구 삭제 기능의 근거→자체 정책→서버/UI→검증을 완료했다. 상세 결과는 `validation/session-02.md`, 삭제 정책은 `ARCHITECTURE.md`에 기록했다. **`npm test` 16개 모두 통과**(기존 11 + 삭제 5). 구문 검사와 `git diff --check` 통과. 기본 sandbox의 localhost 연결 제한은 승인 실행 환경에서 재검증했다.

실제 브라우저에서 삭제 취소/Escape·확정·새로고침 지속성·다른 창의 선택 취소·삭제 후 수신·재추가·숨긴 친구 삭제·연결 실패 후 재시도를 확인했다. 검토 중 새 채팅 모달의 SSE 갱신이 생성 버튼을 다시 활성화하거나 초점을 없애는 문제도 보완했다. 기존 첫 묶음 검증은 `validation/session-01.md`에 보존했다.

이번 변경은 아직 커밋하지 않았다. 기존 `data/messenger.json`은 수정하지 않았다. 자동/UI 검증은 별도 `test-results/` 임시 저장소와 `KATOK_DATA_FILE`, UI 포트 4174로 수행했다. 검증 서버는 종료했다. 실행 데이터와 테스트 임시 저장소는 Git 제외다.

## 주요 결정

1. 처음부터 네이티브 엔진 설치나 큰 역분석에 머물지 않고 친구→채팅의 동작 가능한 사이클부터 만들었다.
2. Node 22가 설치되어 있고 .NET SDK가 없어 의존성 없는 로컬 서버+PC 브라우저를 첫 실행 환경으로 택했다. 데스크톱 포장은 후속 단계다.
3. 관찰한 개념만 참고하고 색상·아이콘·데이터 모델·프로토콜을 자체 작성했다.
4. 숨김/차단/삭제를 하나의 플래그로 합치지 않는다. 숨김은 목록에서만 제외한다.
5. 읽음은 서버 GET/송신으로 처리하지 않고, 클라이언트가 선택한 방의 하단을 실제 표시하며 포커스를 가진 경우 명시 요청한다.
6. 세션 기록의 중심은 이 문서. 기능 추가 시 완료/미확인/다음 작업/검증을 함께 갱신한다.
7. 삭제는 내 방향 친구 관계만 제거한다. 대화 참여와 수신은 친구 등록 여부와 별개이며, 삭제 이력에 의한 자동 등록 제외 기능은 연락처 자동 등록 도입 시 별도 설계한다.
