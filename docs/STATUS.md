1. 이 문서와 `ARCHITECTURE.md`, 현재 `git diff` 및 코드를 읽는다. 첫 세션 중 사용량 제한으로 중단되었던 부분까지 재개하여 통합했다.

3. **다음 최소 기능은 친구 삭제**다. `OBS-R08`, `OBS-UI05`를 먼저 읽고, 삭제와 메시지 수신의 관계·확인/취소 UX를 자체 정책으로 정한 뒤 구현한다. 가능하면 명시된 테스트 대상에서 원본 확인창과 결과를 추가 관찰한다.
4. 이어서 차단/해제. 상충하는 배포 안내를 하나로 확정하지 않는다. 원본 분석을 반복하기 전에 EXE/문자열 파일 SHA-256 변경 여부만 확인한다.

## 구현 완료

- Node.js 기본 모듈 서버 + 독자적인 HTML/CSS/JS 화면. 합성 사용자 4명, localhost 한정.
- 친구 목록/검색, ID 추가·중복/미존재 처리, 숨김/복귀.
- 프로필→1:1, 채팅방 목록/검색, 1:1 재사용, 새 그룹 생성/참여자 보기.
- 두 클라이언트 사이 텍스트 송수신, SSE 상태 갱신, 메시지 저장, 재전송 clientId 중복 방지.
- 방 안 읽음 수와 메시지별 미확인 참여자 수, 단조증가 읽음 커서.
- 저장 실패 시 메모리 롤백/임시파일 정리, Windows 일시 파일 잠금의 제한된 재시도, 손상 파일 덮어쓰기 방지.
- 원본 자산을 사용하지 않은 화면, 합성 이름/상태, 반응형 목록/대화 전환.

## 현재 단계와 검증

첫 기능 묶음의 구현·통합을 완료하고 실제 브라우저 검증을 수행했다. 상세 결과는 `validation/session-01.md`에 기록한다. `npm test` 11개 모두 통과. 읽음 경쟁 버그(송신이 아직 보지 못한 상대 메시지까지 읽는 문제)를 수정하고 1:1/그룹 회귀 테스트를 추가했다.

저장소의 변경은 아직 커밋하지 않았다. 실행 데이터는 `data/`에 있으며 Git 제외다. UI 테스트로 만든 합성 메시지/그룹이 남아 있을 수 있다. 새 상태 검증은 별도 `KATOK_DATA_FILE`을 사용한다.

## 아직 모르는 것 / 미구현

- 원본 친구 검색의 초성·정렬·중복/삭제/차단 상태별 조회 결과.
- 원본 차단 해제 후 재추가 조건: 서로 다른 배포 문자열이 상충한다.
- 원본의 실제 송수신 ACK·재시도·읽음 트리거·동기화·같은 상대 방 재사용 규칙. 현재 정책은 독립 설계.
- 함수/xref/decompile: 네이티브 분석 엔진 미설정. REA MCP 등록은 aligned지만 이번 세션에 도구 미노출, 기존 REA 6.7.0 CLI로 조사했다. 설정 수정이나 엔진 설치는 수행하지 않았다.
- 제품 미구현: 친구 삭제/차단, 연락처 검색, 그룹 초대/탈퇴, 실제 인증·계정, DB·페이지네이션, 다중 PC/인터넷 서비스, 데스크톱 패키징.
- 사용자 전환은 테스트 편의 기능으로 인증을 대체하지 않는다. 단일 JSON 저장은 다중 서버 프로세스용이 아니며 전원 장애까지의 내구성을 보장하지 않는다.

## 주요 결정

1. 처음부터 네이티브 엔진 설치나 큰 역분석에 머물지 않고 친구→채팅의 동작 가능한 사이클부터 만들었다.
2. Node 22가 설치되어 있고 .NET SDK가 없어 의존성 없는 로컬 서버+PC 브라우저를 첫 실행 환경으로 택했다. 데스크톱 포장은 후속 단계다.
3. 관찰한 개념만 참고하고 색상·아이콘·데이터 모델·프로토콜을 자체 작성했다.
4. 숨김/차단/삭제를 하나의 플래그로 합치지 않는다. 숨김은 목록에서만 제외한다.
5. 읽음은 서버 GET/송신으로 처리하지 않고, 클라이언트가 선택한 방의 하단을 실제 표시하며 포커스를 가진 경우 명시 요청한다.
6. 세션 기록의 중심은 이 문서. 기능 추가 시 완료/미확인/다음 작업/검증을 함께 갱신한다.
