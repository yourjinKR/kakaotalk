## 근거와 판독 범위

설치 루트는 `C:\Program Files (x86)\Kakao\KakaoTalk`이다. 아래 `S`는 이 루트 아래 `skin/default/resource/string_merge.xml`을 가리킨다. 원본 파일 SHA-256은 `b724986fc17b644287564bb263e7dd97aea267d5ea0443a6f9d99276a387b5ec`이다. `S:1932`는 이 파일의 1-based 1932행을 의미한다. 선택한 행과 문자열 ID는 [선택 문자열 JSON](evidence/selected-korean-strings.json)에 있다.

`S`, 색상 XML, 폰트 XML은 일반 PowerShell·rg·XML 파서로 읽은 정적 리소스다. 아래에서 **관찰**은 파일에 해당 리소스가 있다는 뜻이며 실제 실행 중 해당 기능이 작동했다는 뜻이 아니다. **구현 판단**은 재현 앱을 위한 선택이다.

## 레이아웃 및 바이너리 한계

`skin/default/layout`에 친구/채팅 XML 이름 파일들이 있지만, 검사한 17개 레이아웃 파일은 읽을 수 있는 XML 텍스트가 아니다. 예를 들어 `MainView.xml`과 `ChatDlg_EX.xml`의 앞 32 bytes는 `39537d0f5aa72e9249dd50df1180838ae5615367ccd904a4dcb51803dcb6f8dd`이다. `FriendListView.xml`의 앞 32 bytes는 `6df2366a345616f41a7e567e60b82755b74e43afc7439f594ccbd7292961652f`이다. 암호화/압축 형식과 복호화 코드는 확인하지 않았다. 파일 이름만으로 크기·간격·활성 기능을 추정하지 않는다.

실제 REA `inspect-pe-resources` Evidence `ev_9a4edcd6f1cc4950ab7e6b369c46b5d0280e35ec3939e46c09c573a3b8a9bb49`는 x86 PE32와 리소스 트리 25개 entry/10개 payload를 확인했다. 타입 ID는 3, 6, 14, 16, 24이다. 원본 byte 범위·payload hash·정적 아이콘 참조가 전체 JSON에 보존되어 있다. 아이콘 그룹 외 payload는 opaque이며 이미지 해석·언어 fallback·실제 Windows 로딩은 관찰하지 않았다. 이 Evidence는 채팅 프로토콜·함수·계정 데이터·레이아웃 복구를 증명하지 않는다.

## 연결 상태

REA 도구가 현재 대화에 연결되어 있지 않아 스킬의 복구 절차에 따라 `npx -y rea-agents@6.7.0 doctor --client codex --json`을 실행했다. sandbox 안 첫 시도는 npm DNS `ENOTFOUND`로 종료했다. 같은 읽기 전용 명령을 네트워크 허용 실행으로 수행한 결과 Codex 등록 및 스킬은 aligned였다. 설정 복구는 필요하지 않았다.

- Node: `22.23.2`, Windows x64.
- 등록: `C:\Users\young\.codex\config.toml`의 `cmd.exe /d /c npx -y rea-agents@6.7.0 mcp`.
- doctor의 요청 범위 `healthy: true`, 전체 환경 `environment_healthy: false`.
- Ghidra/Hopper/IDA/Kuna 등 네이티브 분석 엔진이 구성되지 않았다.
- 현재 세션 MCP 연결은 doctor가 확인할 수 없으며 활성 도구도 없었다. 재연결하면 MCP 도구가 나타나는지 확인할 수 있다.
- 설정 변경, setup 실행, provider 설치 및 대상 실행은 하지 않았다. `inspect-pe-resources`는 provider 없이 CLI에서 성공했다.
