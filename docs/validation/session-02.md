# 친구 삭제 검증 — 2026-10-23 (Asia/Seoul)

## 범위와 근거

독립 localhost 프로토타입의 친구 삭제를 검증했다. 분석은 기존 [OBS-R08](../research/installed-resource-flows.md)과 [OBS-UI05](../research/runtime-ui-observations.md)를 재사용했으며, 새 REA 조사나 원본 카카오톡 UI/관계 변경은 하지 않았다. 원본의 확인창·삭제 완료·재추가 동작은 미확인이다. 삭제의 세부 규칙은 [자체 설계](../ARCHITECTURE.md)에 명시했다.

기존 `data/messenger.json`을 사용하지 않고 합성 사용자와 `test-results/`의 별도 저장소로 검증했다. UI는 `KATOK_DATA_FILE`을 지정한 `npm start`, `http://127.0.0.1:4174`에서 실행했다. 종료 후 검증 서버를 정리했다. 남은 테스트 파일은 Git 제외이며 원본 친구·대화 데이터가 아니다.

## 자동 검증

Node.js 22.23.2, Windows에서 `npm test`: **16 tests passed, 0 failed**. 기존 11개 회귀 테스트와 `test/friend-deletion.test.mjs`의 5개 테스트가 모두 통과했다.

1. 숨긴 친구 삭제 시 내 방향 관계만 제거하고 상대 관계·계정·1:1/그룹방·모든 메시지·읽음 커서를 유지한다. 파일 재개방 후에도 삭제가 유지되며 ID 재추가는 `hidden:false`, 1:1은 기존 방을 재사용한다.
2. 잘못된 대상·자기 자신·미존재 사용자를 거부한다. 동시/반복 삭제 중 실제 제거는 한 번이며 이후에는 `deleted:false`; 저장과 소유자 알림도 한 번이다.
3. 본문 없는 DELETE API를 지원한다. 삭제 후 기존 방에서 양방향 송수신·읽음 처리가 계속 가능하고 재추가 후 이력이 보존된다. 잘못된 URI도 400으로 처리한다.
4. 소유자의 SSE 삭제 알림이 도착했을 때 이미 파일에 삭제가 저장되어 있다.
5. 저장 실패 시 친구/메모리·기존 파일을 유지하고 알림을 보내지 않는다. 독점 생성한 임시파일을 정리하고 실패 원인 제거 후 동일 쓰기 큐에서 재시도할 수 있다.

기본 sandbox의 첫 실행에서는 기존 HTTP 테스트 9개가 `fetch failed`로 실패하고 저장소 테스트 2개는 통과했다. 승인된 localhost 실행 환경에서 전체 16개가 통과했다. 이를 도메인 결함으로 처리하거나 연결 제한을 우회하는 제품 코드를 넣지 않았다.

`node --check public/app.js`, `node --check server/store.mjs`, `node --check server/index.mjs`, `git diff --check` 통과. Git의 LF→CRLF 안내는 공백 오류가 아니다.

## 실제 브라우저 검증

Codex in-app browser의 합성 me/hana 세션을 사용했다.

| 조작 | 확인한 결과 |
| --- | --- |
| 일반 친구 프로필 → 친구 삭제 | 이름/ID, 대화·수신 유지, ID 재추가 안내가 나타나고 기본 초점이 취소에 위치 |
| 취소, 다시 열어 Escape | 요청 없이 확인창이 닫히고 친구 2명과 프로필이 유지됨 |
| 다른 me 창의 새 채팅에서 hana 선택 후 첫 창에서 삭제 확정 | 첫 창 친구 2→1, 프로필 닫힘. 다른 창에서 hana 행·선택이 사라지고 0명 선택, 시작 버튼 비활성, 검색창으로 초점 이동 |
| 새로고침, 채팅 탭 → 기존 1:1 | 삭제 상태가 유지되고 기존 방/안내 메시지가 남음 |
| hana 창에서 기존 방에 합성 테스트 메시지 전송 | 삭제한 me 창에서 새로고침 없이 해당 메시지를 수신 |
| me가 ID `hana`로 재추가 → 대화 시작 | 친구 1→2, 기존 1:1 방과 삭제 후 수신한 메시지가 그대로 표시됨 |
| hana 숨김 → 친구 관리 → 삭제 확정 | 숨긴 친구 1→0, 빈 목록 표시, 친구 관리의 닫기 버튼으로 초점 복귀 |
| jun 삭제 확인창을 열고 검증 서버 종료 후 제출 | 한국어 연결 오류, 확인창·대상·취소/재시도 버튼 유지, 재시도 버튼으로 초점 이동 |
| 같은 합성 저장소로 서버 복구 → 열린 확인창에서 재시도 | 삭제 성공, 친구 0명 빈 상태 표시, 새로고침 후에도 유지 |

일반/숨김 삭제 검증 시 브라우저 콘솔 error 로그는 0개였다. 의도적으로 서버를 종료한 연결 실패 검증에서는 네트워크 오류가 발생하며 정상 상태의 오류 수와 구분한다.

검토에서 발견한 보완: 새 채팅 모달을 SSE로 갱신할 때 생성 중 버튼을 다시 활성화하지 않도록 요청 상태·중복 제출 guard를 추가했다. 체크박스 재렌더 시 남아 있는 대상의 초점을 보존하고, 삭제된 체크박스의 초점은 검색창으로 옮긴다. 오류 표시 뒤 삭제 버튼 초점도 복구한다.

## 한계

원본 카카오톡의 정책을 검증한 결과가 아니다. 삭제 중 장시간 지연·서버 커밋 후 응답만 유실된 상황·재추가와 재시도의 교차·좁은 화면과 전체 키보드 흐름은 실측하지 않았다. 반복 삭제/저장 실패/방 보존은 자동 테스트로 검증했고, 새 채팅 중복 제출 guard는 코드 검토로 확인했다. 삭제는 메시지 차단을 제공하지 않는다.
