# 첫 세션 검증 — 2026-10-23

## 자동 검증

Node.js 22.23.2, Windows x64에서 `npm test`: **11 tests passed, 0 failed**.

1. 방향성 친구 관계, 추가 중복·미존재·자기 자신 거부, 숨김/복귀 후 메시지 유지.
2. 1:1 방 재사용, 그룹별 독립 ID와 참여자 검증.
3. 동시 송신 순번, 동일 clientId 재시도 중복 방지, 다른 본문 충돌 거부.
4. GET의 읽음 무변경, 방 배지와 메시지별 미확인 참여자 수, 커서 단조증가.
5. 미확인 상대 메시지 뒤에 답장을 보내도 읽음 커서가 자동 증가하지 않는 회귀 검증.
6. 그룹에서 각 참여자의 명시적 읽음 전까지 미확인 참여자 수 유지.
7. 비참여자 조회·전송·읽음 거부, malformed JSON·본문 크기·타입 검사.
8. Host/Origin 제한, cross-site 요청 거부, 데이터/소스 파일 외부 제공 방지.
9. 커밋 후 SSE 알림, 저장소를 다시 열었을 때 친구·메시지·읽음 유지.
10. 저장 실패 시 메모리 롤백·기존 파일 보존·임시파일 정리·쓰기 큐 복구.
11. 손상되거나 버전이 다른 파일을 보존하고 시작 거부.

제한된 실행 sandbox에서는 loopback 요청이 `fetch failed`/EACCES로 막혔다. localhost 테스트 실행을 승인된 실행 환경으로 전환한 뒤 위 결과를 확인했다. 첫 재검증에서는 Windows의 일시적 `rename EPERM`이 발생하여 기존 파일 삭제 없이 접근/공유 오류만 25/50/100/200ms 간격으로 제한 재시도하게 수정했고, 이후 11개 모두 통과했다. 원인을 백신이라고 확정하지 않는다.

`node --check public/app.js`, `node --check server/store.mjs`, `git diff --check`도 통과했다. 프런트 변경은 정적 파일이므로 실제 브라우저를 새로고침해 확인했다.

## 실제 브라우저 검증

Codex in-app browser, `http://127.0.0.1:4173`에서 합성 데이터만 사용했다. 원본 카카오톡 계정과 연결되지 않는다.

| 조작 | 확인한 결과 |
| --- | --- |
| 친구 검색에 `하나` 입력 | 김하나 1개 결과, 친구 프로필로 이동 |
| 프로필에서 대화 시작 | 기존 1:1 방 열림, 초기 안내 메시지 표시 |
| me에서 텍스트를 Enter로 전송 | 입력 비워짐, 목록 미리보기 갱신, 발신 메시지 표시 |
| 별도 `?user=hana` 세션 열기 | 안 읽은 메시지 1개, 해당 방에 me의 본문 표시 |
| hana가 방을 열고 답장 | me 창에 새로고침 없이 답장이 표시되고 발신 메시지가 읽음으로 변경 |
| me에서 `sora` 친구 추가 | 친구 수 2→3, 새 프로필 표시 |
| sora 숨김→친구 관리→복귀 | 일반 목록 제외, 숨긴 친구 수 1→0, 일반 목록 복귀 |
| 새 채팅에서 hana/jun 선택 | 선택 2명, 그룹 이름 입력 표시, 나 포함 3인 그룹 생성 |
| Shift+Enter 후 `<b>문자 그대로</b>` 전송 | 줄바꿈 유지, HTML 태그가 서식/코드로 실행되지 않고 본문 문자로 표시 |
| 다른 세션에서 그룹 확인 | SSE로 방과 메시지 표시, 방을 열기 전 안 읽음 1; me의 메시지 미확인 참여자 수 2 |
| hana가 그룹 방 열기 | hana의 방 배지가 없어짐; me 쪽 미확인 참여자 수 1로 변경 |
| 페이지 새로고침 | 추가한 친구와 생성한 방·메시지가 유지됨 |

브라우저 콘솔의 error 로그는 조회 시 0개였다. IME 조합 중 Enter의 방어 코드는 구현했지만 실제 Windows 한국어 IME 조합 시나리오를 자동 실측한 것은 아니다. 응답 유실 상태의 프런트 재시도·장시간 연결 복구·대용량 이력·복수 서버 프로세스는 별도 후속 검증 대상이다.

## 수정된 주요 결함

- 송신 시 읽음 커서를 자동으로 올리던 로직 제거. 상대의 새 메시지가 화면에 도착하기 전에 답장하는 경우의 거짓 읽음을 방지한다.
- 읽음 요청 중 새로운 메시지가 렌더된 경우, 앞선 요청 성공 후 필요한 다음 위치를 이어서 반영한다. 실패 시 무한 자동 재시도하지 않는다.
- 모달로 대화를 가린 동안과 좁은 화면에서 대화 패널이 숨겨진 동안 읽음 갱신을 하지 않는다.
- 저장 실패로 남는 임시 파일을 해당 쓰기가 독점 생성한 파일에 한정해 정리한다.

이 검증은 독립 프로토타입의 동작 검증이다. 원본 카카오톡의 실행 규칙을 증명하지 않는다.
